# Implementation decisions

- Use Python standard-library HTTP, SQLite and plain browser modules rather than React/FastAPI. This enables one-command startup without downloaded dependencies. The domain and runner contract remain independent of the UI.
- Store typed JSON entities in SQLite; immutable context versions, job envelopes and variant directories preserve history. Approval pins the exact variant; revisions create child directories.
- Run jobs in independent background threads and persist state/events. On restart interrupted jobs are marked failed rather than silently resumed. A durable worker queue and cancellation remain future work.
- Built-in fixture directions use actual standalone HTML and native relative navigation. Chrome captures screenshots; screenshot failures are reported as not assessable.
- Discover executables locally. Codex models come from its local cache, OpenCode models from its discovery command; other model IDs are manually entered. Do not invent a current model catalog or imply that cached models are accessible.
- Agent selectors configure safe argument arrays; no shell interpolation or permission-bypass flags. Existing local authentication belongs to the CLI, not the studio.
- Routes follow the design specification, while the initial HTTP mutation API uses concise action endpoints. The full specified REST API/OpenAPI is deferred.
- This implementation is intended for trusted local coding agents, not hostile artifact ingestion or multi-user hosting.

- Research now has in-page status, results and a direct board/generation handoff. Handoff pins finding content and provenance in the board; later global finding selection changes do not silently alter that board's generation/revision inputs.
- Fixture color guidance is deliberately restricted to explicit text/background/button directives. Applied values are recorded on the variation, the source context remains immutable, and a fixture-support warning stays in designer review.

- Research results previously shared an ID with their job, so the job's final save overwrote them. Research records now have their own ID and a `job_id`.
- Approval builds a separate immutable bundle under `storage/prototypes/<id>/` (copy of the variant plus a tiny `_player/nav.js` that only reports the current screen to the player and executes back/forward/state commands). The source variant is untouched. Prototypes belong to a variant; approving another variant moves the approval flag but keeps older bundles.
- Revisions start as `pending` and are accepted or reverted; reverted versions stay in history, hidden by default. Approving a pending revision accepts it. An approved version cannot be reverted.
- Revisions take `annotation_ids` and are validated server-side (open pins on the parent only); used pins become `applied` and cannot be edited or deleted.
- Pin element anchors are resolved in the browser from a hidden, script-disabled frame at screenshot size; if no `data-design-id` element is under the pin, only coordinates are stored.
- Cancel/timeout use `Popen` with the log streamed to `runner.log`, so partial logs survive. Concurrency is limited by `STUDIO_MAX_JOBS`. Retry creates a new job from the stored inputs and links both ways.
- Context saves are deduplicated by content; rule versions increment only when a rule's content changes.
- The client was split into `lib.js`, `store.js`, `views.js` and `app.js`. Polling redraws only when state changes, never while a field is focused or the player is open, and preserves scroll position.

- Reference images are stored under `storage/projects/<id>/references/` with a sniffed (not client-declared) type, 5 MB cap and 40 per project; SVG is rejected. Uploads use a base64 JSON action to keep the stdlib server dependency-free. At launch each job gets its own copy in `jobs/<id>/references/`, its metadata (name, note, SHA-256) is part of the shared input hash, and retries copy from the previous job, not the library. CLI agents receive them as relative file paths in the task text; there is no provider-specific image protocol.
- Generated variations with references always get a designer-review check: the studio cannot verify that an agent used an image.
- The UI follows Figma's structure (layers, frames on a canvas, tabbed inspector, comment tool, floating zoom bar) without copying its assets. Canvas zoom uses CSS zoom plus an auto-fit on entry; the review frame scales its width instead so pin coordinates stay exact.

- CLI runners receive only their `env_allowlist` (editable in Settings; defaults per agent include its auth variable). Nothing else from the studio's environment is inherited. stdin is closed so agents never wait for piped input.
- Package validation is now stricter: manifest structure, 200 files / 20 MB, no symlinks, no external URLs, `@import`, network calls, frames/objects, module imports or external navigation in HTML/CSS/JS, and relative links may use `..` only if they stay inside the package. CSS variables with no fallback and no declaration fail a "Token references" check.
- Failure messages name the cause (missing manifest, bad JSON, unsupported file with allowed types, link and file) instead of raw exceptions. `.md` notes are allowed in agent output.
- Real-agent findings that drove these changes: an agent returned a plan without writing files once (task text now forbids it); another wrote a README and used `../` links (both previously rejected with opaque errors).

- Jobs are rows in SQLite; the in-memory queue holds only IDs and is rebuilt on start (`recover_jobs`). Workers claim jobs atomically (queued to running), so cancel and start cannot both win. Interrupted running jobs fail with a Retry hint instead of silently re-running (a re-run costs model calls). `STUDIO_MAX_JOBS` sets the worker count.
- Region diffs use Python's HTMLParser to locate `data-design-id` elements by offset (no third-party parser). A change is attributed to the innermost identified element; text outside any identified element is reported as "outside". Scope is enforced by a deterministic check, not by trusting the agent.
- Revisions start with `output/` pre-seeded from the parent version. Real agents could not read the parent from an absolute path outside their working directory; editing in place also keeps untouched files byte-identical.
- Blind mode masks identity in `/api/state` (runner name/id, fixture style and tokens, fixture-specific check text) rather than only in the UI, and labels are drawn from a random permutation so completion order cannot leak identity. Approval counts as the blind choice. It is a bias-reduction aid for a single local user, not a security boundary.
- A mix is an ordinary variant (`kind: mix`) with a synthetic `mix_board` job so lineage, approval, prototype and export need no special cases. Source assets are copied to `shared/<source id>/` and screen links are rewritten; links between screens are left alone because screens keep their `N.html` names.

- Blind mode also withholds job files that name the runner (envelope, runner log, raw output) at the HTTP layer; task text and reference images are identical across runners and stay available.
- When an agent emits no `data-design-id`, the studio stamps `auto-<tag>-<n>` anchors before validation and records which screens were stamped; a review item says so. This changes agent markup only by adding attributes, and only when none exist.
- Mix consistency is a heuristic on CSS text (primary font, three most frequent colours). It is deliberately a review item, never a pass.
- Automatic retry is per runner (0 to 3, default 0), only for `failed` and `timed_out`, never after a cancel, with a short backoff and the same inputs. Each attempt is a linked job so history stays honest.
- Sandbox: bubblewrap with `--ro-bind / /`, tmpfs over `/tmp`, the home directory and the studio storage, the job folder bound writable, and the agent's install and auth directories re-bound explicitly. Network is left on because agents call model APIs. Codex's own sandbox needs nested user namespaces, which are denied inside ours, so its flag follows our setting: full-access only inside our sandbox, `workspace-write` otherwise.
- Share links run on a separate `ThreadingHTTPServer` (`STUDIO_SHARE_PORT`) with a handler that knows only `/s/<token>/...`. The studio API and asset routes do not exist on that port, so enabling sharing does not expose the studio. Tokens are random, stored with the prototype, expire optionally and can be revoked; the player is a small static page that only forwards back/forward/state commands to the bundle.

- Per-run experiment overrides are a deep copy of the saved context with extra, replacement or suspended rules and a run-only prose block (`job_context` in `boards.py`). They live on the job (`context.run_overrides`), change the context hash and the shared input hash, and never create a project context version. Run-only prose goes above DESIGN.md and the instruction says it takes precedence, because the experiment showed rule-only overrides lose to un-layered prose. Revisions inherit the parent job's overrides unless new ones are sent.
- The agent self-report is parsed from the tail of `runner.log` by regex (`parse_agent_report`). It is stored as `job.agent_report`, labelled unverified in the UI, never used for pass/fail, and only adds a designer-review item. It is withheld while a board is blind.
- The conflict preview (`conflict_preview`) is deliberately a small keyword table (equal actions, expressive imagery, distinctive voice, motion, urgency) matched against rule text. False positives and misses are expected; it informs the designer and blocks nothing.

- POC hardening: loopback-only `Host` allowlist on the studio port (DNS-rebinding would otherwise reach the runner-registration and job endpoints), JSON-only POSTs, 400 for bad input vs 500 with a request id and server-side traceback for bugs, SQLite WAL with a 30 s busy timeout (workers and request threads write concurrently), ETag on `/api/state` so the 2 s poll is a 304 when nothing changed, and share listener bound to loopback by default. No Docker by request; process management is left to the user's terminal, systemd or similar.
- Code split (no behaviour change): `server.py` became an entry point plus a facade that re-exports the modules and forwards `STORE` to `core`, so tests and `doctor.py` keep `import server as s`. Modules form a strict layering with no import cycles: core -> contexts, fixture, regions, validation, references, research -> jobs -> boards -> prototypes, sharing -> web. Tests that patch a function patch it in the module that calls it.
- UI theme: the coss ui token set is used directly (neutral near-monochrome, `--radius .625rem`, borders 8% black, muted surfaces 4% black, grey focus ring, dark primary, semantic colours only for status). Before the React move the same tokens were applied as a CSS layer over the old stylesheet. Inter is bundled from npm (`@fontsource-variable/inter`), so there are no web-font requests.
- Flow for many runs: variants are grouped into rounds (client-side, derived from job creation time within 8 s and parent links; no new stored field), older rounds fold when a board has more than six variants, failed jobs are one compact dismissible row, and the projects page is a separate home without the project sidebar. `dismiss-job` only sets `job.dismissed`; nothing is deleted.
- UI moved from hand-written ES modules to React 19 + TypeScript + Tailwind v4 + coss ui (Base UI) on the user's request, as a single rewrite rather than a staged one; the old UI is preserved as a zip (see README). State is a tiny external store plus `useSyncExternalStore` (no state library); routing is a small History-API router; dialogs are one host opened imperatively. The Python API did not change except for serving `apps/ui/dist` with SPA fallback and cache headers. The e2e contract (ids, classes, data attributes, accessible names) was preserved so the unchanged Playwright suite validates parity; one test race it exposed (deleting "the last" pin immediately after adding one) was fixed in the test, because React keeps DOM nodes where the old UI rebuilt them. Form selects and checkboxes stay native rather than coss's custom ones so Playwright and screen readers behave identically. Dark mode tokens ship with coss but are not enabled.


## Designer tools (2026-11)

- **Free exploration is a run override, not a project setting.** `free: 'rules' | 'open'` rewrites the job's context copy (no effective rules; for `open`, also no guidelines or tokens) and hashes into the snapshot, so a free run is still reproducible and never changes the saved guidelines.
- **Audit is manual and appended to the variant** (`variant.audits`, last 10) so history stays honest about when it ran and against which documents (docs hash). Identical findings across screens are merged into one row.
- **Review documents are read-only, local, and bounded** (Markdown only, no symlinks, size and count caps) and can only be set from the computer running the studio (`set-review-folder` is in `RUNNER_ADMIN`).
- **Decision log lives on the board** and stores variant ids, not names, so blind boards can hide it until reveal.
